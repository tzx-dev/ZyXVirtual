# ZyX Virtual v0.2.8-beta

## Correções

- O estado persistente agora é marcado enquanto o QEMU está em execução.
- Depois de uma saída abrupta, os discos graváveis são recriados a partir da ROM verificada, evitando reutilizar um `/data` somente leitura ou um QCOW2 interrompido.
- O produto ZyX OS continua sendo compilado como `userdebug` e passa a declarar `ro.debuggable=1`, permitindo `adb root` para desenvolvimento.
- A configuração de desenvolvimento habilita ADB por TCP na porta 5555 dentro do guest.
- Mantido o `virtio-rng-pci` para a inicialização de `keystore2`/`vold`.

## Limite intencional

O modo beta deixa `/data` e o estado da VM graváveis e permite root por ADB. As partições do sistema continuam protegidas pelo modelo Android/AVB/APEX; não são forçadas a read-write, pois isso invalidaria os APEX e poderia impedir o boot. Em uma árvore userdebug completa, alterações de sistema devem usar `adb remount`/overlayfs quando suportadas pelo build.

## Diagnóstico do log de campo

O boot anterior falhava porque `/data` era montado somente leitura. Como consequência, `apexd` não conseguia criar `/data/apex/decompressed`, `vold` não conseguia criar `/data/misc/vold/user_keys` e o init reiniciava para recovery com `init_user0_failed`.
