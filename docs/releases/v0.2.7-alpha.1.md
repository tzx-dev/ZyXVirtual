# ZyX Virtual v0.2.7-alpha.1

## Correções

- Adicionado o dispositivo `virtio-rng-pci` ao QEMU system-mode, reproduzindo a configuração `RNGDevice=true` do pacote UTM upstream.
- A alteração evita a espera/falha de `keystore2`/`vold` durante a criação das chaves do usuário 0 (`init_user0_failed`) no primeiro boot.
- O estado persistente agora recebe um marcador de sessão; após uma saída abrupta, os discos graváveis são recriados a partir da ROM verificada, evitando reutilizar um filesystem `/data` montado somente leitura.
- Mantido o diagnóstico pelo `serial.log` do guest, separado do `qemu.log` do host.

## Validação

- Build Android remoto concluído com sucesso no GitHub Actions.
- Smoke test reproduziu a inicialização do `system_server`; o serviço `activity` ainda precisa concluir a inicialização completa do framework em TCG.
- O log de campo confirmou que `apexd` não conseguia criar `/data/apex/decompressed` e que `vold` não conseguia criar `/data/misc/vold/user_keys` porque o estado persistente estava somente leitura.
